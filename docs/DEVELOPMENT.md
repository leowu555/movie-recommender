# Local development

This is the repeatable startup path for CineRank. Secrets and env vars: [`CONFIGURATION.md`](CONFIGURATION.md).

## Supported runtimes

| Tool | Supported | Verified in this repo |
|------|-----------|------------------------|
| Python | 3.12 or 3.13 (Django 6.0) | Lock compiled with **Python 3.13** |
| Node.js | 20+ (Vite 8) | **24.14** used for lockfile checks |
| npm | 10+ (`package-lock.json` v3) | **11.9** |
| PostgreSQL | 16 | Homebrew `postgresql@16` on macOS |

`python3` on macOS may be Apple’s 3.9, which **cannot** run this project. Use the interpreter that created `backend/venv` (3.13) or another 3.12/3.13 install.

The AWS Lambda movie API was packaged from macOS wheels. That zip is **not** a validated Linux/Lambda runtime image. Rebuild the Lambda bundle on a Linux environment (or Lambda-compatible wheels) before treating it as production-ready.

Do not upgrade Django, React, or Node in this task just because newer releases exist.

## Backend dependencies

- **Direct** packages: `backend/requirements.in` (what we import: Django, DRF, cors, Mangum, NumPy, scikit-learn, psycopg2, dotenv, requests).
- **Locked tree:** `backend/requirements.txt`, generated by [pip-tools](https://pip-tools.readthedocs.io/) `pip-compile` in a **throwaway** venv (not `pip freeze` of `backend/venv`).
- **Install:** `pip install -r requirements.txt`
- **Regenerate lock** (after editing `.in` only): from `backend/`, `./compile-requirements.sh`

`djangorestframework-simplejwt` is not a dependency. Auth remains DRF **TokenAuthentication**.

`narwhals` appears in the lock because **scikit-learn 1.9** requires it; it is not a direct app import.

### Platform note

`psycopg2-binary` and NumPy/SciPy wheels are OS- and architecture-specific. A lock produced on macOS ARM may not install the same wheels on Linux Lambda. Use the same `requirements.in`; recompile or install on the target OS when packaging for AWS.

Lambda package (unchanged workflow):

```bash
cd backend
pip install -r requirements.txt -t build/lambda
cp -R config movies accounts ratings recommendations watchlist manage.py build/lambda/
cd build/lambda && zip -r ../lambda.zip .
```

Handler remains `config.lambda_handler.handler`.

## Frontend dependencies

Keep **npm**. Manifest: `frontend/package.json`. Lock: `frontend/package-lock.json`.

Clean install (uses the lockfile; does not bump versions):

```bash
cd frontend
npm ci
```

`npm install` may update the lockfile; use `npm ci` for a reproducible tree. Do not upgrade packages unless a later task requires it.

## First-time / clean machine startup

Database creation, migrations, and demo seeding are **explicit**. Ordinary `runserver` does not reset data or create demo users.

### 1. PostgreSQL

```bash
brew services start postgresql@16
createdb movie_recommender   # first time only; skip if the database exists
```

### 2. Backend environment

```bash
cd backend
python3.13 -m venv venv          # or another 3.12/3.13 python
source venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

If `venv/` already exists, activate it and install from the lock; this task does not recreate your working venv.

### 3. Environment file

If `backend/.env` **does not** exist:

```bash
cp .env.example .env
python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
```

Paste the key into `SECRET_KEY`. Set `TMDB_API_KEY` and `DB_*`.

If `.env` **already** exists, do not overwrite it. Add any missing keys from `.env.example`.

### 4. Migrations (explicit)

```bash
python manage.py migrate
```

Optional demo accounts (`alice` / `bob` / `carol`, password `demo1234`) — only when you want seed data:

```bash
python manage.py shell -c "exec(open('seed_demo_data.py').read())"
```

### 5. Run API and UI (two terminals)

Terminal A:

```bash
cd backend
source venv/bin/activate
python manage.py runserver
```

Terminal B:

```bash
cd frontend
npm ci          # first time or after lockfile change
npm run dev
```

API: `http://127.0.0.1:8000` · UI: `http://localhost:5173`

### 6. Established checks

From `backend/` with `SECRET_KEY` set (`.env` or the environment):

```bash
python manage.py test config movies
python manage.py check
```

Frontend production build (optional):

```bash
cd frontend
npm ci
npm run build
```

Do not call live TMDB or deploy Lambda as part of ordinary startup.
